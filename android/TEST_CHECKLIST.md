# Bench-Test Manual Verification Checklist

Use this checklist during bench test sessions to verify communication integrity between the Android app and the ESP8266/HC-05 hardware prototype.

| Test Case | Objective | Steps | Expected Result | Pass/Fail |
|---|---|---|---|---|
| **TC-01: Permission Handling & Denial** | Verify graceful behavior when Bluetooth permission is not granted. | 1. In Android App Info, revoke "Nearby devices" permission.<br>2. Open app.<br>3. Check Connect tab. | • Warning card appears: "Bluetooth Permission Required".<br>• App does not crash.<br>• Tapping "Grant Bluetooth Permission" prompts Android permission dialog. | [ ] |
| **TC-02: Bluetooth Disabled** | Verify app handles phone Bluetooth turned off. | 1. Turn off Bluetooth in Android quick settings.<br>2. Return to app. | • App displays "Bluetooth is disabled".<br>• Connect button is disabled.<br>• No exceptions thrown. | [ ] |
| **TC-03: Bonded Device Discovery** | Verify detection of paired HC-05. | 1. Ensure HC-05 is paired in Android Settings.<br>2. Tap refresh icon on Connect tab. | • HC-05 appears with MAC address and "HC-05 DETECTED" tag.<br>• Selecting HC-05 radio button highlights it. | [ ] |
| **TC-04: Successful SPP Connection** | Verify RFCOMM socket establishment with HC-05. | 1. Power ESP8266 & HC-05.<br>2. Select HC-05.<br>3. Tap "Connect to HC-05". | • Status switches to "CONNECTING...", then "CONNECTED".<br>• Top status pill turns green ("HC-05 ONLINE").<br>• HC-05 onboard LED switches to slow double-blink (indicating active SPP connection). | [ ] |
| **TC-05: Disconnect & Clean Teardown** | Verify socket closes cleanly without orphaned threads. | 1. While connected, tap "Disconnect". | • Socket closes.<br>• Status transitions to "DISCONNECTED".<br>• Top pill turns gray.<br>• Re-tapping "Connect" successfully reconnects without restarting the app. | [ ] |
| **TC-06: Schedule Validation (Invalid Input)** | Verify local validation prevents invalid time strings from being sent. | 1. Go to Schedule tab.<br>2. Tap Day 1 Morning.<br>3. Attempt to set `25:00` or `08:99`. | • Dialog validation catches invalid time.<br>• "Send to Device" does NOT transmit malformed JSON. | [ ] |
| **TC-07: Matching Schedule Acknowledgement** | Verify full transmission and matching response ID handling. | 1. Set valid times for all 9 slots.<br>2. Tap "Send to Device". | • App displays "Waiting for device confirmation (Request: [ID])...<br>• ESP8266 receives 9 slots, parses them, updates OLED, and echoes: `{"v":1,"id":"[ID]","ok":true,"cmd":"set_schedule","revision":X}`.<br>• App displays green banner: "✓ Schedule Accepted by Hardware! Revision: X". | [ ] |
| **TC-08: Mismatched Acknowledgement / Stale Response** | Verify app rejects responses with wrong request ID. | 1. Simulate or inject response with wrong `id` (e.g. `{"v":1,"id":"9999","ok":true}`). | • App safely logs the message in Protocol Monitor.<br>• Request does NOT mistakenly mark itself accepted with an alien ID. | [ ] |
| **TC-09: Rejection from Device (invalid_schedule)** | Verify app handles `ok: false` error response. | 1. Have ESP8266 return `{"v":1,"id":"[ID]","ok":false,"error":"invalid_schedule"}`. | • App displays red banner: "Schedule Rejected: invalid_schedule".<br>• Does NOT show "Accepted".<br>• "Retry" button is provided. | [ ] |
| **TC-10: Response Timeout Handling** | Verify graceful timeout when hardware drops power or hangs. | 1. Disconnect ESP8266 power while leaving HC-05 paired or unplug serial line.<br>2. Tap "Send to Device". | • App waits up to 7 seconds.<br>• Shows amber warning: "Response Timed Out for ID [ID]".<br>• Provides "Retry" button. Never freezes UI thread. | [ ] |
| **TC-11: Read-Back Verification (get_state)** | Verify phone compares device memory against phone schedule. | 1. On Schedule tab, tap the sync icon under "Device Read-Back Verification". | • Transmits `{"v":1,"id":"[ID]","cmd":"get_state"}`.<br>• ESP8266 returns its 9 stored slots and revision.<br>• App compares each of the 9 slots. If identical, shows "✓ Perfect Match with ESP8266". If any slot differs, shows exact discrepancy. | [ ] |
| **TC-12: Servo Safety Confirmation Modal** | Verify mandatory safety acknowledgment before actuation. | 1. Go to Bench Test tab.<br>2. Select a slot (e.g. `D2_EVENING`).<br>3. Tap "Test Selected Servo". | • Confirmation modal appears with safety warnings.<br>• "Confirm & Test Servo" button remains DISABLED until user checks "I confirm hands are clear and load is strictly inert". | [ ] |
| **TC-13: Confirmed Servo Actuation** | Verify servo actuation request and acknowledgement. | 1. Check safety acknowledgment box.<br>2. Tap "Confirm & Test Servo". | • Transmits `{"v":1,"id":"[ID]","cmd":"test_servo","slot":"D2_EVENING"}`.<br>• ESP8266 rotates Servo 2, updates OLED, and replies `{"v":1,"id":"[ID]","ok":true,"cmd":"test_servo"}`.<br>• App displays green confirmation banner.<br>• App never refers to actuation as a "medication dose". | [ ] |
| **TC-14: Hardware Power Loss / Disconnect Recovery** | Verify app handles abrupt HC-05 disconnection. | 1. While connected, unplug HC-05 power.<br>2. Check app status. | • Reader loop catches EOF / IOException.<br>• Status transitions to Error: "Lost connection to device".<br>• User can tap Reconnect once hardware is restored. | [ ] |
